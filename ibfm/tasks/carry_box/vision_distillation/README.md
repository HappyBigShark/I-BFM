# 搬箱视觉学生蒸馏（DAgger）

冻结的 I-BFM 教师（Actor + B + 阶段控制器）作为老师，训练一个只依赖机载可得信息的视觉学生。
学生直接接收控制器选出的技能 `z`，部署时不需要 B，也不需要箱子完整位姿。
第二轮起，阶段控制器也可以改读学生辅助头的箱子估计（`DISTILL_CONTROLLER_SOURCE=estimate`）。

## 学生观测

| 输入 | 内容 |
|---|---|
| 掩码编码器 | `[箱子掩码, 掩码已知区域]`，60×106 |
| 深度编码器 | `[归一化深度, 有效, 超远, 箱子掩码]`，60×106。任务范围 0.2–4.0 m 内的有效深度归一化到 [0,1]；没有回波的像素填哨兵值 −1，同时 `有效`=0（表示未知，不等于超远）；有回波但超过 4 m 的像素 `超远`=1。掩码通道来自最近一帧掩码，比深度旧，二者之间的错位是有意保留的 |
| 低维（515） | 关节/重力/角速度、动作历史、上一步动作、机身系目标位置、机身系双手位置、29 个关节的估计力矩、10 项掩码/深度统计，以及深度、掩码两路各自的观测年龄 |
| 技能 | 控制器混合后的 `z`（256 维） |

10 项统计（`vision_sensor.STATS_NAMES`）：
- 去掉掩码边缘后的 D435i 中位深度及其有效位（使用和掩码同一时刻的深度帧）
- 掩码面积、掩码内有效深度比例、深度 IQR
- 检测框质心、宽高（按 848×480 全分辨率计算）、是否检测到

中位深度表示**箱子可见表面沿光轴的深度**，不是箱子中心的距离。
不使用箱子尺寸：训练时每个场景的箱子各维随机取 0.25–0.40 m。

**不使用 Depth Anything。** 它在 Jetson 上的时延和内存都难以放进控制环；而且评估表明，控制器所需的箱子估计并不依赖它：
教师执行、控制器读估计值时，强制让 Depth Anything 无效，成功率不降（0.77 → 0.81）。
注意，已经带着它训练好的学生不能在部署时直接去掉：同样的测试里，学生从 0.68 掉到 0.22，因为"检测到箱子但 Depth Anything 无效"
这种组合在训练中从未出现过。所以去掉它需要重新训练。

**根高度来自腿部正运动学。** 学生输入里"机身系目标位置"的 z 分量，用的是骨盆比最低那只脚高多少（按重力方向），
不用骨盆高度真值。仿真中，它和真值的误差中位数为 0.2 mm、p95 为 0.9 mm（只在双脚同时离地的 0.4% 时刻达到 1–3 cm）。
训练时叠加每回合固定偏置 σ = 1 cm、每拍噪声 σ = 0.3 cm，代表编码器、连杆和脚底的标定误差。机身的 x、y、偏航仍是真值（相当于里程计已知）。

**接触不作为输入。** 学生输入的是 29 个关节的估计力矩，对应 G1 底层状态里由电流估算的 `tau_est`，按各关节力矩上限归一化。
仿真里取作动器实际输出的力矩，加每回合固定偏置（σ 为上限的 2%）、比例误差（σ = 5%）、每拍噪声（σ 为上限的 1%）和 1 拍延迟。
手部接触和是否承重由辅助头从力矩、视觉和本体信息中推断；物理接触真值只用作训练标签。

输出：29 维动作，以及 15 维辅助头。辅助头预测：
- 机身系箱子位置、速度，离开初始高度的距离，直立度，偏航角速度
- 左右手接触，以及"机器人独自承重"（箱子只接触机器人，不接触地面或平台）
- 机身线速度：x、y 在航向坐标系，z 为世界竖直方向

前两组覆盖了阶段控制器读取的全部箱子相关指标。**阶段控制器的决策不读机身线速度**（只用 IMU 的偏航角速度和里程计位置），
所以速度输出只用于监督和评估，为以后替换里程计做准备；它也促使共享特征更好地编码自身运动，箱子的世界速度估计依赖这一点。
每个回合的结果里记录速度估计的平均误差、p95 和静止误报率（真实速度 < 0.05 m/s 时估计 > 0.15 m/s 的比例）。

## 仿真感知（`vision_sensor.py`）

- **渲染**：用 `mj_multiRay` 在 CPU 上做光线投射，得到光轴深度 Z 和 geom id，不需要 OpenGL。
  在地面上与解析解的误差 < 0.001 mm；MuJoCo 渲染器的深度缓冲有约 1–4 cm 的误差。
  D6000 上的用户没有 `/dev/dri` 权限，EGL 不可用，这是改用光线投射的直接原因。
- **相机**：G1 头部 RealSense D435i，使用 P-BFM 在 G1 上标定的位姿（`pbfm/perception/instinct_direct_depth.py`）：
  `torso_link` 上 (0.0488, 0.01, 0.4378) m，光轴向下 48.0°，垂直视场 58.29°。与 Unitree URDF（47.6°）相差不到 1 cm、0.4°。
  躯干、骨盆和腰部的网格从来不会被头部相机看到，而且这个位置落在躯干和头部网格内部，所以这些网格排除在光线投射之外：
  速度从每帧 14.4 ms 降到 5.2 ms，图像逐像素不变。场景可见性检查也做同样的排除。
- **安装误差**：每回合固定一次，在相机坐标系下位置 ±1 cm，横滚、偏航 ±2°，俯仰 ±5°（参考 P-BFM 的随机化；P-BFM 的俯仰是 ±10°，
  这里缩小到 ±5°，否则"开局可见"的场景筛选会失效）。
- **两路各自计时**：

  | 流 | 频率 | 延迟 | 依据 |
  |---|---|---|---|
  | D435i 深度 | 25 Hz | 每帧随机 1–3 拍（20–60 ms） | 硬件深度 |
  | 掩码（YOLO-World + NanoSAM） | 6.25 Hz | 180 ms | Jetson 实测 153–161 ms 模型时间，5.3–5.7 FPS |

- **不在环内运行 NanoSAM**，改为模拟它的误差：
  - 掩码：按全分辨率检测框判断能否检测（短边 ≥ 12 px；远处的箱子在 60×106 网格上只有一两个格），
    网格上看不到箱子时再用一条中心光线判断是否被遮挡；彩色视场 69°×42° 以外标为未知；
    每帧 5% 漏检；边界随机膨胀或腐蚀；检测框加 3 px 噪声
  - D435i：每回合深度尺度 0.95–1.05、偏置 σ = 3 cm（参考 P-BFM 的 RP1 噪声和 php_parkour）；随机量程 2.5–6 m；
    一半回合有整幅失效时段（每秒 0.15 次，每次 0.5–4 s）；3×3 高斯模糊（σ = 1，只在有效像素之间）；
    误差 σ=0.004·z²；深度跳变边缘 30% 空洞；随机 1% 空洞；毫米量化；0 表示无效
- 部署时，用 `pool_full_resolution()` 把 848×480 的 Z16 深度和对齐后的掩码池化到同样的 60×106 网格：
  每格取有效像素的中位数，不和无效像素做插值；掩码按半数以上像素判定。
  检测框用 `detection_from_bbox()` 转成同样的归一化统计。

## 场景（`run_collectors.py`、`scene_visibility.py`）

- **相机视场决定了可训练的范围。** 头部 D435i 向下俯仰约 48°，相机高 1.27 m，即使正对箱子，
  也只有在约 1.25 m（箱高 0.8 m）到 2.5 m（箱高 0.15 m）以内才可能看到；超过 3 m 时任何高度都看不到。
  所以远处的问题不是 D435 打不到，而是 RGB 也看不到。
- 第二轮只训练**开局时箱子可见**的场景：距离 1.0–2.5 m，机器人朝向箱子、偏差 ±25°。
  每个场景生成后，按开局站姿计算可见的初始箱高区间（`visibility.json`），要求在名义安装角和俯仰误差两个极端（±5°）下都可见；
  回合的初始箱高只在该区间内随机，没有可见高度的场景直接丢弃。实际约 70% 的场景被接受，2.2 m 以上的基本被排除。
  箱子尺寸每维随机 0.25–0.40 m。
- 教师验证（每种 30 个回合，只跑教师）：
  - 0.25–0.40 m 的各种尺寸（包括非正方体）：放置成功率 0.83–0.93
  - 0.20 m 正方体：只有 0.60
  - 初始距离 4–8 m（真值控制器）：0.90

## 阶段控制器读估计值（`DISTILL_CONTROLLER_SOURCE=estimate`）

- 所有箱子相关指标都从辅助头的估计重建：距离、目标距离、高度、离地高度、速度、直立度、偏航角速度、左右手接触。
  具体做法是在真实 MjData 的副本里替换箱子的位置和速度，并把机器人放到正运动学根高度上，再调用原来的指标函数；
  机器人的 x、y、偏航仍然使用真值（相当于里程计已知）。
  技能选择用到的箱子方向、目标方向也一样替换。
- **估计预热**：开局的估计还没收敛（GRU 没有历史），前 30 拍（0.6 秒）控制器不做阶段切换，保持在接近阶段；
  第 30 拍用已收敛的估计重新选择 z-aware 的高度档位（通过控制器自己的 `reset()`）。没有预热时，
  控制器曾在第 1 拍就因为偏小的距离估计切换到抬起，导致约一半回合的高度档位没有被重选。
  控制器构建时读到的初始箱高也换成了 z-aware 自己的"无信息"默认值，不读真值。
- 控制器决定的 `z` 本身也是学生的输入，所以每拍用的是上一拍的估计；第一拍先用接近阶段的 `z` 让学生预跑一次
  （不推进 GRU 状态）得到初始估计。读估计值模式下，`controller_truth_metric_calls` 记录控制器读到真值的次数，必须为 0。
- 每个回合的 `outcomes.jsonl` 记录估计指标相对真值的平均误差，以及双手接触的误判率。

## 训练流程

```
run_collectors.py (CPU, N 个 worker) ──回合文件──▶ incoming/ ──原子认领──▶ train_student.py (DDP)
        ▲                                                                        │
        └────────── status.json（β、γ、ckpt/latest.pt） ◀─────────────────────────┘
```

- 每个回合是一个进程，运行和 `z_aware_height_banded_sim2sim.py` 相同的控制器栈，并在最外层装上 `distill_probe.py`。
  每拍都记录教师动作作为标签。β 决定这个回合由教师还是学生执行（DAgger）；γ 决定阶段控制器读真值还是读估计值。
  **回合跑满 30 秒，不提前结束。** 第一轮在"完成后保持 2 秒"时提前结束，导致学生几乎没见过完成之后的站立状态：
  固定种子跑满 30 秒时，学生成功率只有 0.48，而在完成后 2 秒结束时是 0.86。
- 学习端每个 rank 维护内存回放（默认每卡 150 万拍），采样长度 48 的序列，前 16 拍只做 GRU 预热、不计损失。
  损失 = 动作 MSE + 0.1 × 辅助损失。后台线程负责读入回合和组装批次，GPU 不等数据。
- `--init-checkpoint` 热启动：低维输入层的列、它的归一化统计以及辅助头的各行**按名称对应**：
  删掉的输入列丢弃，保留的列复制，新输入列置零，新输出行从初始化开始；其他参数要求形状一致。
  检查点会保存列名（`low_columns`、`aux_columns`）；更早的检查点按已知的旧布局对应。
  配合 `--beta-warmup-steps 0` 时，热启动后的权重在启动时就发布，β 从 `--beta-start` 开始，
  回放从一开始就包含学生回合。之前一次微调先用 1000 步只采教师回合，学生成功率曾一度跌到 0.17。

## 一阶段训练

可以从零开始，一次训练完成，不需要热启动。但必须保留"先真值、后估计值"的逐步切换：
辅助头还没训练好时，如果控制器就读估计值，会在错误的时机切换阶段，那段时间采到的数据基本没用。

```bash
RUN_DIR=$PWD/runs/distill_onestage_<tag> GPUS=0,1,2,3 WORKERS=180 bash launch.sh \
  --beta-warmup-steps 3000 --beta-decay-steps 30000 \
  --gamma-start-steps 20000 --gamma-ramp-steps 20000 --gamma-max 0.8 \
  --max-steps 150000 --batch 192 --prefetch 8
```

学习端的后台线程负责组装批次，并把数据放进锁页内存；深度按 int16 传输，主线程只发起异步拷贝。
这样 4 张卡的利用率可以保持在 98–100%。

## 运行（D6000）

```bash
cd ~/wujianhao/i-bfm/ibfm/tasks/carry_box/vision_distillation
# 第二轮：从第一轮热启动，γ 在 1.5 万步后用 2 万步升到 0.8
RUN_DIR=$PWD/runs/distill_round2_<tag> GPUS=0,1,2,3 WORKERS=180 bash launch.sh \
  --init-checkpoint $PWD/runs/distill_20261015/ckpt/step_0300000.pt \
  --beta-warmup-steps 2000 --beta-decay-steps 20000 \
  --gamma-start-steps 15000 --gamma-ramp-steps 20000 --gamma-max 0.8 \
  --max-steps 150000 --batch 128
```

固定种子配对评估（`evaluate.py`，只用 CPU）。所有模式使用相同的场景、箱高和噪声种子；默认跑满 30 秒，与第 0 步相同：

```bash
../../../.venv/bin/python evaluate.py --output-dir runs/eval_<tag> --checkpoint <ckpt> \
  --episodes 100 --visible-start --box-size random --distance-min 1.0 --distance-max 2.5 \
  --controller-source estimate   # 或 truth
```

监控：
- `learner.log` 和 `metrics.jsonl`：损失、回放规模、预取队列长度，以及按"执行者 × 控制器来源"分组的最近 200 个回合的放置成功率、抬起率、跌倒率
- `collectors.log`：各组合的回合数和失败数；`failures/` 下是失败回合的日志
- `outcomes.jsonl`：每个回合的结果，包括估计指标误差、D435 量程和失效时长

停止：先 `touch <run>/STOP`，采集端会在当前回合结束后退出。学习端：先 `kill -- -$(cat <run>/learner.pid)`，
torchrun 的工作进程各自有独立的进程组，所以再用 `pgrep -f "train_studen[t].py"` 确认是否已全部退出。

## 已知局限

1. **箱子开局必须在视野内。** 箱子在远处或身后时，需要粗略位置先验、搜索行为，或者调整相机角度。
2. 机器人位姿使用真值，相当于里程计已知；目标位置也是真值。
3. 误差模型是占位值，需要用真机的 NanoSAM / D435i 输出、关节力矩和腿部正运动学来标定。
4. 只覆盖搬箱；推箱、踢箱有各自的控制器快照。
5. 学生在 CPU 上逐拍推理，用于采集；部署时的推理延迟需要另外测量。
